# TUI 改版「极简风」实施计划（Claude Code 式 · 纯终端 · 跨平台 · 轻量 · 启动快）

## 一、设计（用户将看到什么）

```
墨斗 v0.4.3 · glm-4.5-air · default                    ← 欢迎行（启动即出，dim）

  ❯ 把 utils.js 里重复的解析逻辑抽成函数                 ← 用户消息（cyan ❯）
  ⚙ read {"path":"src/utils.js"}                        ← 工具调用（dim）
    ↳ 142 行                                            ← 工具结果（缩进）
  抽取公共函数时发现三处重复…（流式增量在此渲染）

  ✻ 抽取公共函数… (esc 中断 · 12.3s · 第 5 步)          ← 忙碌行：spinner+摘要+计时+步数

╭──────────────────────────────────────────╮
│ ❯ 输入任务，/ 开头为命令…                 │            ← 输入卡（round 边框+placeholder）
╰──────────────────────────────────────────╯
  /plan /init /skills /mcp …（Tab 补全 · Ctrl+C 退出）     ← 命令提示行

 glm-4.5-air · default │ ↑1.2k ↓345 $0.013 │ ▐███░░░░░ 31% ctx   ← 状态栏（单行三段）
```

设计原则：
1. **历史区静默、底部区活跃**——消息历史用 Ink `<Static>` 冻结不再每帧重渲；屏幕底部常驻三个活动块：忙碌行/输入卡、命令提示行、状态栏。
2. **一行状态栏讲完全部状态**——`模型 · 模式 │ ↑in ↓out $成本 │ ctx 剩余%`（进度条 10 格，≥80% 黄色预警、≥95% 红色，联动 compaction 阈值）。
3. **忙碌行取代黑盒**——busy 时输入卡收起，显示自绘 spinner（✻✽✜✢✣✲✳，120ms/帧）+ 最近工具动作 + `(esc 中断 · 秒数 · 第 n 步)`；Esc 键新增为任务中断。
4. **零新依赖**——spinner/进度条全部手写，不引第三方库；符号选 Unicode BMP（Windows conhost 兼容）。
5. **流式节流**——text_delta 每 token 一次 setState 改为 60ms 缓冲 flush（每秒 ≤17 帧），长回复不卡。

## 二、代码改动（11 任务，TDD 一任务一提交）

**Phase 1 状态栏**
- T1 新建 `StatusBar.tsx` 三段式组件（替换 CostBar）：model·mode │ tokens·cost·预算 │ ctx 进度条分色
- T2 数据接通：LoopBundle 导出 `contextWindow`（factory 已持有 capabilities）；index.tsx 传 settings(provider/modelId/permissionMode) + contextWindow 给 App

**Phase 2 输入卡**
- T3 InputBox→InputCard：round 边框 + placeholder + 欢迎行 `墨斗 vX · model · mode`
- T4 斜杠命令补全：commands.ts 导出 `SLASH_COMMANDS` 清单，输入 `/` 显示匹配提示行，Tab 补全

**Phase 3 忙碌行**
- T5 新建 `BusyLine.tsx`：自绘 spinner + 最近 tool_call 摘要 + `(esc 中断 · 计时 · 步数)`；app.tsx 加 Esc 键中断（复用 taskAbortRef，与 Ctrl+C 双击退出并存）
- T6 流式节流：ref 缓冲 + 60ms interval flush；assistant_message 到达先 flush 再清空

**Phase 4 消息区**
- T7 历史条目切 `<Static>`（只渲染新增，历史不重渲）；items 拆 history + 动态区
- T8 视觉统一：图标缩进对齐（⚙/↳/✗）、PlanConfirm 的 📋 换 ⎘（conhost 兼容）、审批标题加粗

**Phase 5 启动提速**
- T9 factory MCP 连接串行改 `Promise.all` 并行（单失败不阻断不变）
- T10 TUI 先行：render 提前到 factory 之前，App 增 `bundle: LoopBundle | null`（初始 null）；装配期欢迎行+输入卡立即可见（placeholder 变"正在装配上下文…"、提交拦截），就绪后切换并追加"✓ 上下文就绪"；bundle 为 null 时 /plan /resume 等提示稍候

**收尾**
- T11 README 新界面示意 + docs/dev.md 组件结构更新 + backlog（主题系统、鼠标支持记入不做）

## 三、验收标准
1. 启动 <300ms 可见欢迎行与输入卡（MCP/repo map 后台装配不白屏）
2. busy 可见 spinner/最近动作/计时，Esc 真能中断
3. 状态栏实时三段式，ctx ≥80% 变黄
4. `/` 补全 + Tab 生效
5. 长流式回复 60ms 节流不卡
6. Windows Terminal 与 conhost 符号均正常
7. 253 测试全绿零回归（审批/计划/回滚/MCP/Skills 可用）

## 四、明确不做
不换 TUI 框架、不加鼠标支持、不做主题配色（记 backlog）、不做虚拟滚动（Static 已解决重渲）、不改 core 事件协议（TUI 只消费现有 ModouEvent）。

预计 12–16 净工时，每 3–4 任务一次人工检查点。计划详情已定稿将写入 docs/plan-tui.md。
